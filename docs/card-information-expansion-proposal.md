# 카드 정보 레이어와 확장 장비 배치 제안

> 초기 제안 기록입니다. 이후 사용자의 구현 요청과 ‘표시 개수 제한 없이 자동 축소’ 선택을 반영했습니다. 실제 동작은 [장비 등록·카드 구성·시트 내보내기](equipment-and-composition.md)를 따릅니다. 아래의 축소 제한과 선택 인물 중심 배치 제안은 최종 구현에 적용하지 않습니다.

이 문서는 다음 카드 편집 기능의 설계 제안이다. 이번 변경에서 적용한 Lucian 안내·언어·테마 UI와 구분하며, 기존 카드 데이터나 `DESIGN.md`를 바꾸지 않는다.

## 레이어와 겹침

기본은 `정보 앞`이다. 모든 장비명이 읽히고, 현재 미리보기·PNG 레이어 계약에도 맞는다.

`인물 앞`은 배경 제거된 인물에만 제공하고 `글자 보호`를 기본으로 켠다. 인물이 종이 노트의 빈 가장자리를 살짝 덮는 것은 허용하되 글자 영역은 보호한다. 보호할 공간이 부족하면 정보를 옆 정보열이나 별도 상세 시트로 보낸다. 원본 스크린샷처럼 전체 사각형이 불투명한 이미지는 정보 뒤 배치에 적합하지 않다.

이미지에 CSS padding이나 투명 여백만 더해도 절대 배치된 정보 박스가 자동으로 밀리지는 않는다. `정보 간격`은 이미지 크롭·확대와 독립된 카드 레이아웃 값으로 둔다. 화면에서는 인물과 정보 사이 여백을 조절하고, 내부에서는 정보 박스 위치를 이동하거나 전용 정보열 폭을 확보한다.

자동 겹침 방지는 배경 제거 마스크를 낮은 해상도의 점유 영역으로 한 번 계산·캐시하고, 그 외곽을 여백만큼 확장해 글자 배치 금지 영역으로 사용할 수 있다. 박스를 좌우 정보열의 후보 위치에 배치하되 인물 얼굴·손·의상, 제목과 다른 정보 박스를 피한다. 미리보기와 PNG가 같은 배치 결과를 사용해야 한다. 매 드래그 이벤트마다 원본 해상도 마스크를 다시 검사하지 않는다.

권장 조작은 `레이어: 정보 앞 / 인물 앞`, `글자 보호: 기본 켬`, `정보 간격`의 세 가지다. 선택권은 유지하면서 기본 결과가 읽히도록 한다.

## 장비 보관과 카드 표시를 분리

캐릭터에 장비를 모두 저장하는 것과, 한 장의 카드에 모두 표시하는 것을 별도 상태로 관리한다. 편집기에는 그룹별 장비 목록과 `카드에 표시` 선택을 제공한다. 긴 목록을 카드 위에 자동으로 쌓거나 글자를 계속 줄이지 않는다.

| 그룹 | 저장할 항목 | 카드 배치 |
| --- | --- | --- |
| 의상 | 머리·몸·손·다리·발 | 기존 5개 노트가 기본 |
| 무기 | 주무기·보조무기 | 선택 노트 또는 상세 시트 |
| 장신구 | 귀걸이·목걸이·팔찌·왼손/오른손 반지 | 작은 보조 목록 또는 상세 시트 |
| 얼굴장식 | 별도 컬렉션 항목 | 필요할 때 강조 노트 |
| 패션소품 | 우산·날개 등 별도 컬렉션 항목 | 이미지 가까운 강조 노트 또는 상세 시트 |
| 직접 입력 | 공식 검색에서 찾지 못한 항목과 메모 | 별도 사용자 항목 목록, 가짜 itemId를 만들지 않음 |

얼굴장식과 패션소품은 일반 `Item` 장비 검색과 같은 데이터라고 가정하면 안 된다. 공식 게임 문서도 별도 컬렉션/슬롯으로 설명한다. 검색 원본을 검증하기 전에는 직접 입력 경로를 둔다.

## 인원수에 따른 결과

- 1인: 인물이 큰 룩 카드에 주요 의상과 선택한 강조 항목을 배치한다. 전체 장비는 2열 상세 시트에 묶는다.
- 2인: 각 인물의 좌우 정보열을 유지한다. 장신구·소품이 많으면 캐릭터별 상세 페이지를 추가한다.
- 3–5인: 라인업을 표지로 사용하고, 선택한 한 인물의 정보 또는 캐릭터별 상세 페이지로 이어진다. 다섯 인물의 모든 항목을 한 화면에 축소하지 않는다.

내보내기는 `룩 카드`와 `전체 장비 시트`를 구분한다. 여러 장을 내보내는 경우 PNG를 캐릭터별 파일명으로 묶어 제공하는 흐름이 적합하다.

## 구현 순서와 데이터 경계

현재 편집기 저장 슬롯은 `head/body/hands/legs/feet`로 고정돼 있다. 검색 서버는 무기를 알고 있지만 장신구 분류 일부를 제외하며, 카드 배치와 정규화 코드도 5슬롯을 전제로 한다.

먼저 저장 위치 키와 검색 분류를 분리한다. 예를 들어 `ringLeft/ringRight`는 각각 저장하되 같은 반지 검색 분류를 사용한다. 다음으로 초안 마이그레이션·정규화·아이템 캐시·장비 편집기·검색 인덱스를 확장하고, 마지막으로 정보 표시 선택과 공유 레이아웃/PNG 상세 시트를 구현한다. 기존 다섯 항목은 그대로 보존하고 새 필드는 빈 값으로 시작한다.
