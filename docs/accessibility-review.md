# 접근성 중심 코드 검토

## 범위와 우선순위

현재 로컬 작업 트리를 검토했다. Git 원격이 없으며 연결된 GitHub의 `ff14` 검색 결과도 없어 원격 저장소와의 동일성은 확인하지 못했다. 모든 기존 파일이 untracked 상태여서 커밋 간 비교 대신 현재 구현을 기준으로 수정했다. DESIGN.md는 변경하지 않았다. 안내된 memory, protocols, .agent, design-md 스킬은 이 작업 폴더에서 발견되지 않았다.

1. 기능 접근을 막는 키보드 문제
2. 선택 상태와 비동기 피드백의 보조기술 전달
3. 포커스 가시성 및 좁은 화면

## 검증

Edge headless / Playwright에서 건너뛰기 링크, 라디오 선택 및 단일 Tab 진입점, 서체 변경 후 포커스, Enter 업로드 파일 선택기, 입력창 실행 취소, 접힌 목록의 검색 단축키, 검색 상태 메시지를 확인했다. 페이지 실행 오류는 없었고 390px 뷰포트에서 문서 가로 넘침이 없었다. 모바일 스크린샷도 확인했다.

`node --check app.js`, `scripts/check-style-seams.ps1`, `node scripts/test-cloudflare-functions.mjs` 통과.

브라우저 회귀 검증: 로컬 서버를 실행하고 Playwright와 Edge가 있는 환경에서 `node scripts/check-accessibility.cjs` 실행. Playwright가 프로젝트 외부에 있으면 `PLAYWRIGHT_MODULE`에 해당 모듈 경로를 지정한다.

## 남은 검증

WCAG 전체 준수를 인증하는 결과는 아니다. VoiceOver/NVDA 실제 낭독, 모든 인원수·카드 배경·업로드 이미지 조합, 운영체제 텍스트 확대 및 실제 브라우저 줌 조작은 별도 검증이 필요하다. 모바일 카드의 작은 장비 텍스트는 다음 디자인 검토 대상으로 남긴다. macOS/VoiceOver 환경은 이번에 사용하지 않았다.

## 2차 검토: 대비와 좁은 화면

- 보조 텍스트가 회색 배경 위에서 4.14:1, 사이드바에서 4.44:1로 측정됐다. 기존 Neutral 팔레트의 chart-3/chart-1을 편집 UI에 적용해 대비를 개선했다. DESIGN.md 및 카드 레시피는 변경하지 않았다.
- 검색창 placeholder를 기존 텍스트 토큰으로 통일하고, 입력창·select 경계를 강화했다.
- 중복 배경 프리셋 저장 폼은 제거하고 단색·패턴·질감 직접 선택만 남겼다. `hidden="until-found"`는 예외로 유지한다.
- 투명 처리된 체크박스 대신 화면에 보이는 스위치에 키보드 포커스 링을 표시한다. 꺼진 스위치도 대비가 확보된 토큰으로 표시한다.
- 320px에서 헤더의 액션 영역 때문에 문서가 329px로 넘쳤다. 작은 화면에서 브랜드와 액션을 두 행으로 분리하고 헤더를 일반 문서 흐름에 배치했다. 업로드 보조 문구는 8px에서 12px로 키웠다.
- 다시 실행 버튼에 남아 있던 고정 색상도 테마 텍스트 토큰으로 교체했다.

### 재현 가능한 검증

`node scripts/audit-contrast.cjs`로 실제 Edge에서 렌더링한 색상을 sRGB로 변환해 상대 휘도와 대비를 계산한다. `PLAYWRIGHT_MODULE` 및 선택적으로 `TEST_BASE_URL`을 지정할 수 있다. 결과는 `artifacts/accessibility-contrast.json`에 저장한다.

| 테마 | 패널 | 텍스트·입력 경계·힌트 검증 항목 | 최소 텍스트 대비 | 기준 미달 |
| --- | --- | ---: | ---: | ---: |
| 밝게 | 꾸미기 | 140 | 4.61:1 | 0 |
| 밝게 | 장비 | 66 | 4.61:1 | 0 |
| 어둡게 | 꾸미기 | 140 | 7.80:1 | 0 |
| 어둡게 | 장비 | 66 | 8.08:1 | 0 |

일반 텍스트/힌트는 4.5:1, 입력 경계는 3:1을 검사한다. CSS 전환이 끝난 상태에서 측정한다. 사용자 이미지와 카드 내부, 그라데이션·필터·요소 opacity에 따른 실제 픽셀 대비는 이 검사의 범위 밖이다. 전체 테마 상태나 검색 결과 데이터의 모든 조합을 보증하지 않는다.

640px·320px에서 꾸미기/장비 패널의 문서 가로 넘침 없음, 숨긴 폼 비노출, 스위치의 포커스 링 및 Space 전환을 확인했다. 이는 1280px 기준 200%·400% 확대에 해당하는 CSS 너비의 reflow 검증이며 실제 브라우저 줌이나 OS 글자 확대 검증과 구분한다. 모바일 결과는 `artifacts/accessibility-320.png`로 확인했다.

이전 키보드 회귀 검사, JavaScript 구문 검사, 스타일 경계 검사도 다시 통과했다.

기준: [W3C 텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [WCAG 2.2 Reflow](https://www.w3.org/TR/WCAG22/#reflow).

## 3차 검토: 캐릭터 편집 흐름과 장비 가독성

캐릭터 선택을 Enter로 실행했을 때 꾸미기 선택기·캔버스·장비 선택기 모두 `document.activeElement`가 BODY로 바뀌는 문제를 브라우저에서 재현했다. 공통 `replaceCharacterButtons` 함수가 기존에 포커스된 캐릭터 키를 보존하고 재렌더 후 해당 버튼으로 복원하도록 변경했다. 캐릭터 및 장비 슬롯의 선택 상태는 `aria-pressed`로 전달한다.

Tab으로 미선택 캐릭터에 이동한 뒤 방향키를 누르면 기존 선택 캐릭터가 움직이던 문제도 수정했다. 이제 포커스된 캐릭터를 선택한 뒤 이동·확대·축소·맞춤을 실행한다. 브라우저의 Ctrl/Meta/Alt 조합은 가로채지 않는다. 카드의 다인 장비 정보를 열면 장비 패널의 해당 캐릭터 버튼으로 포커스를 옮긴다.

장비 패널의 캐릭터 선택기를 자동 줄바꿈 그리드로 바꿔 5인에서도 이름과 번호를 볼 수 있게 했다. 장비 이름은 14px, 부위·영문명은 12px로 표시하며, 긴 한글과 공백 없는 영문명도 줄바꿈한다. 검색 결과에도 같은 읽기 규칙과 테마 색상을 적용했다. 카드 이미지와 PNG 출력의 구성·크기는 변경하지 않았다.

`node scripts/check-character-accessibility.cjs`는 실제 브라우저에서 다음을 검증한다.

- 세 캐릭터 선택 위치의 Enter 실행 후 포커스 및 선택 상태 유지
- 방향키가 포커스된 캐릭터만 움직이고 다른 캐릭터의 transform은 보존
- 카드 장비 정보 → 해당 캐릭터 편집 → 슬롯 → 검색 → 결과 연결 흐름
- 긴 한국어·영문 이름의 줄바꿈
- 320px에서 1/2/5인 선택기 및 다섯 장비 슬롯의 가로 넘침 없음

아이템 API는 테스트 데이터로 대체해 네트워크와 관계없이 UI 동작을 재현한다. 실제 아이템 API 품질을 검증하는 테스트는 아니다. `audit-contrast.cjs`에도 검색 결과 테스트 데이터를 추가했다. 이전 키보드 회귀 검사와 스타일 경계 검사도 통과했다.

캔버스 미리보기 자체의 작은 장비 텍스트는 이미지 조합의 일부로 남아 있다. 확대해 읽을 수 있는 정보는 장비 패널에서 제공하지만, 모든 카드 배경·업로드 이미지 조합의 시각 대비와 VoiceOver/NVDA 실사용 검증은 여전히 남아 있다.

## 4차 검토: 실행 취소와 저장 상태

브라우저에서 다음 문제를 재현하고 수정했다.

- 배경을 바꾼 뒤 실행 취소하면 화면은 원래 배경이지만 localStorage 초안은 변경된 배경이었다. 스냅샷 복원 후 렌더와 저장을 함께 수행한다.
- 실행 취소·다시 실행 버튼은 이력 유무를 표현하지 않았다. 공통 `syncHistoryControls`가 `aria-disabled`와 시각 상태를 동기화한다. Tab 접근을 유지해 마지막 취소 후에도 포커스가 사라지지 않으며, 이력이 없을 때 기존 동작 검사가 변경을 막는다.
- 제목에서 Escape를 누르면 잠깐 복구한 값이 blur 핸들러에 의해 다시 변경된 텍스트로 덮어써졌다. 편집 DOM도 원래 내용으로 복원한 후 편집을 종료한다.
- 제목·부제목이 스냅샷에서 빠져 있었다. 두 필드를 포함하고 편집 시작부터 종료까지를 한 이력으로 기록한다. 입력 중 기본 텍스트 실행 취소는 계속 보존한다.
- 외곽선·그림자 슬라이더는 이력과 저장이 누락됐다. 공통 바인딩으로 첫 input에서 변경 전 상태를 기록하고 change/blur까지의 연속 입력을 한 취소 단계로 처리한다.
- 외곽선 색상·그림자 방향·장비 연결에도 저장 호출을 추가했다. 장비 연결 저장이 추가 다국어 조회의 성공 여부에 의존하지 않는다.

`node scripts/check-history.cjs`에서 이력 버튼 상태, 마지막 취소 후 포커스, undo/redo 후 저장값, 새 편집 시 redo 초기화, Escape 취소, 제목 복원, 키보드 슬라이더 조작, 연속 슬라이더 입력의 단일 취소, 새로고침 후 제목·외곽선 복원을 검증했다. 연속 슬라이더 입력은 브라우저 DOM 이벤트로 재현하며 실제 포인터 드래그를 자동화한 검사는 아니다.

기존 키보드·캐릭터 편집 테스트, 검색 결과를 포함한 대비 검사 420항목, JavaScript 구문 검사, 스타일 경계 검사도 통과했다. 실행 취소 이력 자체는 기존처럼 세션 메모리에만 존재하며 새로고침 시 초기화된다.
## 5차 검토: 비동기 작업과 선택 상태

검색과 배경 제거가 진행되는 동안 사용자가 다른 입력을 할 수 있다는 전제로 경쟁 상태를 점검했다.

- 검색 입력이 바뀌면 debounce 대기 중인 타이머와 진행 중인 `fetch`를 즉시 무효화하고, 결과 영역을 비운다. 각 요청에는 증가하는 `requestId`가 있어 늦게 도착한 이전 응답은 렌더링하지 않는다. 슬롯·언어·캐시 키는 요청 시점의 값으로 고정한다. 검색 중 결과 컨테이너에는 `aria-busy="true"`를, 완료·오류·취소 시에는 `false`를 둔다.
- 장비를 연결한 뒤 다국어 이름 보완 요청을 기다리는 동안 포커스는 즉시 검색창으로 돌아간다. 보완 요청이 끝난 뒤 다시 렌더링해도 현재 선택된 캐릭터·슬롯의 흐름을 빼앗지 않는다.
- 배경 제거는 시작 시 룩, 캐릭터 인덱스, 캐릭터 객체, 원본 URL을 고정한다. 사용자가 다른 캐릭터를 선택하거나 원본을 교체·되돌리면 객체/원본 검사가 실패해 결과 URL을 해제하고 적용하지 않는다. 처리 중 버튼은 `disabled`와 `aria-busy`를 유지한다.
- 비동기 결과가 버려졌다는 사실은 토스트로 안내하고, 다른 캐릭터의 상태나 저장 데이터를 변경하지 않는다.

`node scripts/check-async-accessibility.cjs`는 실제 Edge에서 테스트 API를 지연시켜 빠른 `alpha` → `beta` 검색을 재현하고, `beta` 결과가 보인 뒤 늦은 `alpha` 결과가 나타나지 않는지 확인한다. 이어 배경 제거 요청을 멈춘 상태에서 캐릭터를 바꾸고 응답을 완료해 첫 캐릭터만 `cutout=true`가 되는지, 새 선택 상태와 `aria-busy`가 유지되는지, 페이지 오류가 없는지 검사한다. 이 테스트는 외부 API의 품질이나 추론 결과를 평가하지 않는다.

비동기 작업의 오류 메시지는 기존 토스트와 검색 `role="status"` 영역을 사용한다. 네트워크가 끊긴 상태에서 재시도 버튼을 제공하는 동작은 아직 추가하지 않았다.

## 6차 검토: 스크린리더 시맨틱 구조

역할 없는 `div`에 `aria-label`만 붙어 있던 영역을 명시적인 그룹으로 연결했다. 캐릭터 배치, 캐릭터 선택, 장비 선택, 룩 장비, 그림자 방향 패드는 이제 이름 있는 `role="group"`으로 탐색된다. 장식용 방향 중앙점은 `aria-hidden`으로 숨긴다.

탭과 패널은 기존 `aria-controls`·`aria-labelledby` 관계를 유지하면서 실제 표시 상태를 검사한다. 줌 값, 현재 이미지 상태·파일명·메타데이터, 장비 패널의 현재 캐릭터는 `aria-live="polite"`로 연결해 선택 변경을 기다리는 사용자에게 상태를 전달한다. 결과 검색의 `role="status"`와 `aria-busy`는 비동기 검토에서 추가한 계약을 유지한다.

`node scripts/check-screen-reader-semantics.cjs`는 실제 Edge에서 main 랜드마크, 탭/패널 연결, 이름 있는 그룹, 숨겨진 패널, 현재 캐릭터 상태, 라이브 영역을 확인한다. 실제 VoiceOver/NVDA의 발화 순서와 한국어 음성 품질은 이 자동 검사로 보증하지 않는다.

## 7차 검토: 브라우저 접근성 트리

Edge DevTools Protocol의 `Accessibility.getFullAXTree`로 브라우저가 실제로 노출하는 접근성 트리를 확인했다. `main`은 `투영세트메이커2 편집기`, 캔버스 영역은 `룩 캔버스`, 작업 모드는 `tablist`로 노출된다. 카드 제목·설명은 이름 있는 `textbox`로, 주요 편집 영역은 이름 있는 그룹으로 노출된다. 선택된 꾸미기 탭도 AX 트리에서 `selected=true` 상태로 확인했다.

아이콘의 장식 공백 때문에 `PNG 내보내기 `와 ` 새 룩`처럼 이름이 흔들리던 버튼에는 명시적 `aria-label`을 추가했다. 스크린리더는 이제 아이콘을 제외한 안정적인 이름을 받는다.

`node scripts/check-ax-tree.cjs`는 노출된 AX 노드 363개에서 필수 랜드마크·역할·이름·선택 상태를 확인하고, 화면에 보이는 button/input/select/contenteditable 중 이름 없는 컨트롤을 찾는다. 이 검사는 Edge의 한국어 음성 발화 자체를 실행하지 않으므로 VoiceOver/NVDA 수동 확인은 남아 있다.

## 8차 검토: 카드 미리보기 텍스트 레이어

카드 미리보기는 인원수에 따라 정보 구조가 달라지므로 8개 배경(종이·미스트·진주·장미·물빛·황혼·먹빛·차콜)과 1·2·3·5인 상태를 모두 순회했다. 1·2인 레이아웃에서는 장비 정보 버튼이 보이는지, 각 패널이 90% 이상 불투명한지, 장비명에 접근 가능한 이름이 있는지 확인했다. 3·5인 레이아웃에서는 기존 장비 목록이 숨겨지고 캐릭터별 정보열이 정확한 수만큼 보이는지, 원본·혼합 이미지 위 정보열의 로컬 대비 보호 배경이 유지되는지 확인했다. 제목은 전체 폭 후광 없이 선택형 글리프 외곽선으로만 대비를 보강한다. 제목·설명 편집 필드의 이름과 내용, 캔버스 내부 버튼의 이름, 문서 가로 넘침도 같은 상태에서 검사했다.

`node scripts/check-card-readability.cjs`가 총 32개 상태를 실제 Edge에서 통과했다. 마지막 차콜·5인 상태의 렌더 결과는 `artifacts/accessibility-card-readability.png`로 확인했다. 장비 패널은 카드 안의 작은 텍스트를 읽을 수 있는 대체 편집 경로로 유지된다.

이 검사는 패널 불투명도와 구조를 보장하지만, 사용자가 업로드한 이미지의 모든 픽셀과 텍스트 조합에 대한 WCAG 대비 인증은 아니다. 이미지 위 제목·정보열의 실제 픽셀 대비와 VoiceOver/NVDA의 낭독 품질은 수동 검증이 남아 있다.

## 9차 검토: 확대·표시 모드와 포인터 목표

320px·640px·데스크톱 뷰포트에서 `prefers-reduced-motion: reduce`, `forced-colors: active`, 어두운 색상 모드를 함께 켜고 실제 Tab 입력으로 주요 검색·탭·내보내기·업로드·캔버스 제목 컨트롤에 도달했다. 문서 가로 넘침과 포커스 표시 누락은 없었다. 카드 제목·설명은 카드 스타일의 `outline: 0`보다 높은 우선순위로 키보드 표시를 복원했고, forced-colors에서도 `CanvasText` 테두리를 사용한다.

헤더에서는 편집 흐름과 직접 관련 없는 공유 버튼을 제거하고, 내보내기만 주요 실행 동작으로 남겼다. 카드 안의 짧은 설명 텍스트는 내보내기 캔버스의 편집 영역이라 24px 포인터 목표 검사에서 별도 예외로 기록한다.

`node scripts/check-display-modes.cjs`가 세 뷰포트와 표시 모드 조합을 통과했다. 이 검사는 실제 OS 확대율과 VoiceOver/NVDA 음성 출력을 에뮬레이트하지 않는다.

## 10차 검토: 이미지 패널 UI/UX 일관성과 상태 모션

첨부된 이미지 패널을 기준으로 UI/UX 개편을 이어갔다. 정보 구조와 `DESIGN.md`의 Neutral 방향은 유지하면서, 서로 다른 높이와 밀도로 보이던 조작부를 하나의 리듬으로 정리했다.

- 프레임·확대·위치 조작부를 공통 36px 높이와 6px 간격으로 맞췄다. 프레임 segmented control도 같은 높이를 사용한다.
- 원본/배경 제거 상태를 텍스트만으로 두지 않고 상태 pill로 표현했다. 배경 제거가 완료되면 짧은 강조 모션으로 상태 변경을 알린다.
- 이미지 카드와 썸네일, 업로드 drop zone에 hover·drop 대상 피드백을 추가해 현재 조작 대상을 구분한다.
- 배경 제거 중에는 버튼 내부에 진행 sweep을 표시하고, 완료 문구는 기존 `aria-busy`·버튼 이름 흐름을 유지한다. 장식 모션은 `aria-hidden`으로 접근성 트리에 노출하지 않는다.
- `prefers-reduced-motion: reduce`에서는 진행·강조·호버 전환을 끄고 색상과 상태 텍스트만 남긴다.

시각 결과는 [이미지 패널 검토 캡처](../artifacts/ui-image-panel-after.png)에서 확인할 수 있다. 자동 회귀 검사는 `node scripts/check-ui-consistency.cjs`로 실행하며, 공통 포커스·강제 색상·320px reflow 검사는 `node scripts/check-display-modes.cjs`로 함께 확인한다. 이 검사는 모션 토큰과 레이아웃 리듬을 보증하지만 실제 기기에서의 터치 감각, VoiceOver/NVDA 발화, OS 확대율은 별도 수동 검증이 필요하다.

## 11차 검토: 장비 선택 흐름과 검색 상태

장비 패널도 이미지 패널과 같은 상태 언어를 사용하도록 정리했다.

- 캐릭터 선택기, 장비 슬롯, 검색 결과의 선택·hover 상태를 `--primary` 기반의 동일한 경계와 부드러운 상승 피드백으로 맞췄다.
- 장비 슬롯의 `변경`·`연결`을 compact pill로 바꾸고, 비어 있는 슬롯은 점선과 안내 문구로 구분했다. 선택된 슬롯은 아이콘과 액션 pill이 함께 강조된다.
- 캐릭터 선택 버튼은 최소 44px, 장비 행은 최소 52px, 검색 결과 액션은 32px로 맞춰 포인터·키보드 조작 리듬을 통일했다.
- 검색 중에는 `aria-busy="true"`와 기존 status 문구를 유지하면서 장식용 진행 bar를 표시한다. 진행 bar와 검색 결과의 `＋` 기호는 `aria-hidden`으로 실제 이름을 오염시키지 않는다.
- `prefers-reduced-motion: reduce`에서는 선택 상승, 액션 이동, 검색 진행 애니메이션을 제거하고 상태·색상만 남긴다.

`node scripts/check-equipment-ui.cjs`가 캐릭터·슬롯 선택 상태, action pill 크기, 검색 진행 상태, reduced-motion, 320px 가로 넘침을 확인한다. 결과 캡처는 [장비 패널 검토 캡처](../artifacts/ui-equipment-panel-after.png)다. 카드 본문과 연결되는 장비명은 기존처럼 줄바꿈 가능한 전용 편집 경로로 유지한다.

## 12차 검토: 배경 단색·패턴·질감 선택기

배경 선택기를 다시 비교해 보니 단색에만 예전 정사각 타일과 `::after` 외곽선이 남아 있었다. 패턴·질감과 같은 세 축인데 카드 구조와 선택 표시가 달라 보이는 원인이었다.

- 단색 버튼도 패턴·질감과 같은 24×30px 미리보기 + 라벨 구조로 바꿨다.
- 세 그룹의 카드 높이, `--radius-sm` 반경, hover 상승, `--primary` 선택 테두리와 내부 강조를 통일했다.
- 단색의 레거시 `aspect-ratio: 1`과 선택 pseudo-border를 제거해 겹친 네모 테두리를 없앴다.
- 단색은 3열로 맞춰 패턴과 같은 카드 리듬으로 배치하고, 질감은 두 선택지를 읽기 쉬운 2열로 유지했다.
- 각 그룹의 radio 상태와 세 축의 독립 저장은 유지하며 `prefers-reduced-motion`에서는 전환을 멈춘다.

`node scripts/check-background-ui.cjs`가 세 그룹의 카드 높이·반경·미리보기 크기, 선택 상태, 320px reflow, reduced-motion을 검증한다. 결과는 [배경 선택기 검토 캡처](../artifacts/ui-background-panel-after.png)에서 확인할 수 있다.

## 13차 검토: 카드 타이포그래피와 배경 선택

카드 설정 안에서 제목 서체 선택, 굵기 미리보기, 세부 스타일 토글, 배경 선택이 서로 다른 높이와 선택 표현을 사용하던 부분을 정리했다.

- 제목 서체 select를 36px 조작 높이로 맞추고, 굵기 미리보기는 같은 `--radius-sm`과 `--primary` 선택 표시를 사용한다.
- 굵기 radio는 기존 roving tabindex와 화살표 이동을 유지하면서 hover·선택 피드백과 reduced-motion 처리를 추가했다.
- 세부 스타일 토글을 36px disclosure row로 정리하고 열림 상태를 배경·경계로 표시한다.
- 배경 패턴 썸네일은 작은 화면에서도 서로 다른 소재와 색온도를 식별할 수 있도록 직접 선택 카드 안에서 구분한다.
- 현재 배경 조합 라벨에 `aria-live="polite"`를 추가해 단색·패턴·질감 조합 변경을 상태로 전달한다.

`node scripts/check-typography-ui.cjs`가 서체·굵기 높이와 radio 포커스, disclosure 상태, reduced-motion, 320px reflow를 확인한다. 결과 캡처는 [타이포그래피 패널 검토 캡처](../artifacts/ui-typography-panel-after.png)다.

## 14차 검토: 카드 문구 입력과 긴 텍스트

카드 제목·설명이 캔버스의 고정 한 줄 슬롯과 `overflow: hidden`을 공유해, 직접 입력 중에도 긴 문장이 말줄임으로 가려지는 문제를 재현했다.

- 오른쪽 꾸미기 패널에 `카드 문구` 섹션을 추가했다. 제목·설명 textarea는 전체 초안을 안정적인 작업 영역에서 보여주며, 최대 글자 수와 현재 입력 수를 함께 표시한다.
- 입력 중에는 캔버스 미리보기가 즉시 갱신된다. 제목은 Enter로 저장하고, 두 필드 모두 Escape로 편집 시작 전 값으로 되돌릴 수 있다. blur 한 번을 하나의 실행 취소 단계로 기록한다.
- 캔버스에서 직접 편집하는 흐름은 유지하되, 포커스 중에는 제목 블록이 자동으로 확장되고 줄바꿈·전체 overflow를 허용한다. 포커스가 끝나면 내보내기 카드의 안정적인 한 줄 슬롯으로 돌아간다.
- 입력 영역에는 명시적 label, 안내 문구, live 글자 수, primary 포커스 링을 제공한다. textarea는 내용 높이에 맞춰 자동 확장하고 320px에서도 가로 넘침이 없다.

`node scripts/check-text-editor.cjs`가 두 입력값의 초기 동기화, 미리보기 즉시 반영, 글자 수, Enter 저장, Escape 취소, 캔버스 직접 편집 줄바꿈, 320px reflow를 실제 Edge에서 확인한다. 결과 캡처는 [카드 문구 검토 캡처](../artifacts/ui-text-editor-after.png)다.

## 15차 검토: 모바일 하단 레일과 포커스 가시성

320px 화면에서 장비 패널을 열면 고정 하단 레일이 아이템 검색창의 아래쪽을 덮는 상태를 재현했다. 브라우저의 기본 포커스 스크롤은 레일을 인식하지 못해, 캔버스 장비 버튼에서 검색창으로 이동한 뒤에도 입력창이 레일 아래에 남았다.

- 모바일 루트에 하단 스크롤 여백을 지정하고, 장비 인스펙터 끝에도 안전 영역을 추가했다. 마지막 장비 행까지 스크롤해도 레일 아래에 콘텐츠가 숨지 않는다.
- 장비 패널을 열거나 캔버스 장비 정보·장비 행·검색 결과에서 검색창으로 포커스를 돌릴 때, 검색창이 레일 위 12px 여유를 두고 보이도록 자동 스크롤한다. 데스크톱에서는 기존 스크롤 동작을 유지한다.
- `env(safe-area-inset-bottom)`을 사용해 노치가 있는 모바일 브라우저에서도 레일과 콘텐츠 사이의 여백을 보존한다.

`node scripts/check-mobile-rail.cjs`가 320px 실제 Edge에서 패널 진입, 캔버스 장비 바로가기, 페이지 끝의 마지막 장비 행을 레일 위에 표시하는지와 가로 넘침·스크롤 여백을 검사한다. 이 검사는 실제 모바일 브라우저의 주소창 축소·확대와 VoiceOver/NVDA의 포커스 발화는 시뮬레이션하지 않는다.

## 16차 검토: 별 패턴과 이미지 배치 조작

별 패턴이 넓은 카드에서 성기고 작게 읽히던 문제와, 이미지 크기·위치를 여러 번 버튼으로 눌러야 맞출 수 있던 흐름을 함께 개선했다.

- 별 모티프를 31개로 늘리고 큰 별과 작은 별을 섞어 깊이를 만들었다. 화면 미리보기와 PNG 내보내기는 같은 좌표 배열을 공유하며, 별 패턴의 대비도 함께 조정했다.
- 이미지 크기에 70~180% 슬라이더를 추가했다. 기존 축소·확대 버튼과 현재 퍼센트, 프레임 맞춤은 유지해 빠른 조작과 정밀 조작을 모두 지원한다.
- 위치에는 가로·세로 슬라이더와 현재 오프셋, 중앙 복귀 버튼을 추가했다. 카드 위 드래그와 방향키 미세 조정도 그대로 사용할 수 있다.
- 새 range 입력은 실제 24px 포인터 목표를 확보하고, 명시적인 한국어 이름과 live 크기 값을 제공한다. `prefers-reduced-motion`에서는 장식 전환을 추가하지 않는다.

`node scripts/check-image-placement.cjs`가 별 모티프 수·크기, 크기·위치 슬라이더의 미리보기 반영, 중앙 복귀, 320px 가로 넘침, range 접근성 이름을 실제 Edge에서 확인한다. 별의 최종 픽셀 대비와 다양한 업로드 이미지에서의 최적 배치는 별도 시각 검토가 필요하다.

## 17차 검토: 카드 직접 배치 편집 모드

크기·위치 슬라이더가 이미지 패널 안에서 다른 조작과 섞여 처음 보는 사용자에게 복잡하게 보이는 문제를 줄였다.

- 이미지 패널에는 현재 상태 요약과 `크기·위치 편집` 진입 버튼만 남겼다. 세부 조작은 별도 팝업이 아니라 카드가 그대로 보이는 직접 배치 모드에서 처리한다.
- 모드가 열리면 상단 탐색·인스펙터를 접고 실제 카드의 선택 캐릭터만 강조한다. 카드 위 드래그가 곧 이미지 이동이며, 하단 모드 바에서 크기·위치 복원·가로·세로 미세 조정·프레임 맞춤을 이어서 조작한다.
- 열 때 현재 배치를 임시 초안으로 보관하고 `적용`할 때만 하나의 실행 취소 단계와 저장을 만든다. `취소`나 Escape는 초안과 포커스를 원래 상태로 되돌린다.
- 모드 바는 이름·설명·닫기 버튼을 가진 `region`으로 노출한다. 선택 캐릭터에 포커스를 옮기고 설명을 연결해 방향키 이동과 스크린리더 안내가 같은 편집 대상을 가리키도록 했다. 다른 캐릭터는 포인터 이벤트를 받지 않아 실수로 선택이 바뀌지 않는다.

`node scripts/check-image-placement.cjs`는 직접 배치 모드 진입, 중복 미리보기 제거, 실제 카드 드래그·키보드 이동, 적용·취소·Escape 복원, 모바일 가로 넘침과 접근성 이름을 확인한다. 실제 모바일 브라우저의 핀치 줌 제스처와 VoiceOver/NVDA 발화는 별도 수동 검증이 필요하다.

## 18차 검토: 카드 제목 halo 경계(해결 전 기록)

2인 카드와 캔버스 크게 보기에서 제목 뒤 흰색 halo가 카드 상단·좌측 경계에서 잘려 보이는 상태를 재현했다. 제목 블록의 음수 inset을 카드가 `overflow: hidden`으로 잘라내는 구조가 원인이었다. 아래의 조치는 당시 중간 해결안이며, 현재 최종 동작은 31차 검토에서 후광 자체를 제거한 상태다.

- halo를 제목 블록의 음수 inset pseudo-element에서 카드 전체 헤더의 bounded radial gradient로 옮겼다.
- 헤더 영역 전체를 하나의 stacking context로 두고 제목 텍스트만 포인터 이벤트를 유지해, gradient 경계가 이미지·장비 레이어와 끊기지 않게 했다.
- 당시 `scripts/check-title-halo.cjs`가 경계 클리핑을 확인했다. 현재 파일은 하위 호환용 이름으로 남아 `check-title-outline.cjs`를 호출한다.

## 19차 검토: 캐릭터 이미지 전환 안정성

1번 이미지를 편집한 뒤 2·3번 캐릭터로 이동할 때 이미지 색상이 한 프레임 깜빡이는 현상을 점검했다. 선택 변경마다 `portraitWrap` 내부 이미지를 다시 생성하고 `filter` transition을 적용하던 조합이 원인이었다.

- 캐릭터 선택만 바뀔 때는 기존 이미지 DOM을 유지하고 선택 class·`aria-pressed`만 동기화한다. 실제 이미지 교체·인원수 변경 때만 전체 캐스트를 다시 렌더링한다.
- 이미지 filter에는 transition을 적용하지 않고, 위치 transform과 선택 opacity만 애니메이션한다. 색상 상태가 중간 프레임에서 번쩍 바뀌지 않는다.
- `scripts/check-character-switching.cjs`가 이미지 노드 보존, 선택 상태, filter 상태를 실제 Edge에서 확인한다.

## 20차 검토: 이미지 배치 편집 도크의 시각적 위계

기존 이미지 편집 팝업은 카드 하단을 크게 가리고, 크기·위치·실행 취소 영역이 서로 떨어져 보여 현재 조작 순서를 읽기 어려웠다. 직접 배치 모드의 의미는 유지하되 조작면을 작은 하단 도크로 다시 구성했다.

- 도크를 `설명 → 크기 → 위치 → 취소·적용` 순서의 한 줄 그리드로 배치해 카드가 계속 주 작업 영역으로 보이게 했다. 세로 공간을 차지하던 빈 본문과 중복 구분선을 제거했다.
- `프레임에 맞춤`과 `위치 복원`은 각각 `맞춤`, `중앙`으로 짧게 표시하고, `aria-label`과 `title`에는 동작 전체를 남겨 시각적 밀도와 접근 가능한 이름을 함께 맞췄다.
- 위치 미세 조정은 닫힌 disclosure로 시작한다. 열었을 때만 슬라이더와 방향 버튼이 나타나며, 모바일에서는 같은 순서를 세로로 쌓고 크기 슬라이더가 최소 100px 폭을 확보한다.
- 설명 문장은 시각적으로 반복하지 않고 `aria-describedby`로 유지했다. 취소·적용은 같은 행의 마지막 실행 영역에 두어 사용자가 초안을 버리거나 확정하는 위치를 다시 찾지 않게 했다.

`node scripts/check-image-editor-dock.cjs`가 875px 데스크톱 도크의 접힌 높이, 미세 조정 확장 높이, 320px 모바일 가로 경계와 슬라이더 폭을 실제 Edge에서 확인한다. `node scripts/check-image-placement.cjs`는 이 도크 안에서의 드래그·키보드 이동과 적용·취소 계약을 계속 검증한다.

## 21차 검토: 헤더 우선순위와 언어 선택

헤더의 KR·EN·JP segmented control은 현재 언어의 의미가 약하고, 공유 버튼은 카드 편집의 다음 행동과 관계없이 같은 무게로 노출되고 있었다.

- 공유 버튼과 연결 이벤트를 제거하고 PNG 내보내기만 헤더의 주요 실행 버튼으로 남겼다.
- 언어는 `한국어`·`English`·`日本語`가 보이는 native `select`로 바꿔 현재 상태와 선택 가능한 값을 한 컨트롤에서 이해하게 했다. 데스크톱에서는 `언어` 레이블을 함께 보이고, 모바일에서는 선택값을 유지한 채 레이블만 줄인다.
- select는 키보드·브라우저 기본 선택 동작을 유지하면서 `aria-label`, 명확한 option 이름, `focus-visible` 링을 제공한다. 변경된 언어는 기존 저장 흐름을 통해 새로고침 후에도 유지된다.

`node scripts/check-header.cjs`가 공유 버튼 제거, 언어 option·접근 가능한 이름, 언어 저장·복원, 320px 가로 넘침과 내보내기 버튼 목표 크기를 실제 Edge에서 확인한다.

## 22차 검토: 캔버스 도구막대의 동작 언어

캔버스 상단 도구막대는 이전·다음 탐색과 실행 취소를 두 줄로 나누고, `취소`라는 짧은 표기가 이미지 편집의 취소 동작과 겹칠 여지가 있었다.

- 탐색과 기록 조작을 하나의 가로 명령 행으로 묶고, 기록 그룹 앞에만 구분선을 두어 카드와 도구의 관계를 빠르게 읽게 했다.
- 실행 취소의 시각 표기를 `되돌리기`로 바꾸고 `다시 실행`과 같은 문장 구조로 맞췄다. `aria-label`과 `title`은 기존의 명확한 이름을 유지한다.
- 버튼 높이와 Neutral 토큰을 헤더·인스펙터와 맞추고, 320px에서는 전체 명령 행이 한 줄 안에서 가로로 넘치지 않도록 간격과 패딩을 줄인다.

`node scripts/check-canvas-toolbar.cjs`가 데스크톱 한 줄 배치, 명확한 실행 취소 표기, 320px 가로 경계와 각 버튼의 뷰포트 내 위치를 실제 Edge에서 확인한다.

## 23차 검토: 우측 인스펙터 정보 구조

우측 인스펙터를 다시 읽어 보니 현재 편집 대상과 이미지 작업의 다음 단계가 서로 다른 위치에 흩어져 있었다. 캐릭터를 바꾼 뒤에도 어떤 대상이 선택됐는지 헤더에서 바로 확인하기 어려웠고, 이미지 추가가 배치·배경 제거 뒤에 있어 첫 행동이 분명하지 않았다.

- 캐릭터 구성 헤더에 `선택 대상`과 `캐릭터 01 · 1인` 형태의 live 요약을 추가했다. 기본은 빈 1인 슬롯이며, 캐릭터를 바꾸거나 인원수를 바꾸면 선택 번호와 전체 인원이 함께 갱신되고 `aria-live="polite"`로 전달된다.
- 이미지 섹션의 순서를 소스 카드 → 이미지 추가 → 프레임 → 크기·위치 배치 → 배경 제거 → 짧은 안내로 재배치했다. 사용자의 실제 작업 순서와 화면의 시각적 위계를 일치시켜 다음 행동을 찾는 시간을 줄인다.
- 이미지 추가 영역은 58px 이상, 주요 이미지 조작은 36px 리듬, 배경 제거는 42px 목표를 유지했다. 320px에서도 선택 요약과 이미지 조작이 가로로 잘리지 않는다.
- 선택 요약은 장식용 배지가 아니라 현재 대상을 설명하는 상태 텍스트로 두고, `--primary`는 실행 동작과 포커스에만 사용했다. `prefers-reduced-motion` 규칙은 기존 이미지 패널 계약을 그대로 따른다.

`node scripts/check-inspector-ia.cjs`가 초기·캐릭터 03 선택 상태의 요약, 이미지 작업 순서, live 속성, 버튼 목표 크기, 데스크톱·320px 가로 넘침을 실제 Edge에서 확인한다. 결과 캡처는 [인스펙터 정보 구조 검토 캡처](../artifacts/ui-inspector-ia-after.png)와 [모바일 캡처](../artifacts/ui-inspector-ia-mobile-after.png)다.

## 24차 검토: UI 폰트 계약

`DESIGN.md`에는 이미 UI·본문에 Pretendard를 사용하라는 규칙이 있었고, 문서 헤드에도 Pretendard Variable 웹폰트 로드가 선언돼 있었다. 실제 토큰을 추적한 결과 초기 레거시 `--display`가 Bahnschrift·DIN Condensed를 먼저 가리키고 있어, 해당 선언이 나중의 Neutral 토큰에 가려지더라도 유지보수 중 다시 적용될 위험이 있었다.

- 레거시와 최종 토큰의 `--display`를 `--sans`에 연결해 워드마크, 룩 목록, 인스펙터 제목, 버튼과 입력창까지 Pretendard 계열을 사용하게 했다.
- 카드 제목은 `--card-title-font`로 별도 주입되는 선택 서체 영역으로 남겼다. 이는 디자인 지침의 “Display title choices are intentional variants” 예외이며 페이지 UI 폰트와 섞이지 않는다.
- 외부 Pretendard stylesheet는 표준 `rel="stylesheet"`로 로드하고 `font-display: swap`을 유지해 초기 폴백과 실제 폰트 전환을 안정적으로 처리한다.

`node scripts/check-font-consistency.cjs`가 Edge의 계산된 `font-family`, `--sans`·`--display` 토큰, Pretendard 로드 상태를 워드마크·룩 목록·인스펙터·버튼·검색 입력에서 확인한다. 결과 캡처는 [폰트 일관성 검토 캡처](../artifacts/ui-font-consistency-after.png)다.

## 25차 검토: 헤더 입력 경계 대비

대비 자동 감사에서 헤더 언어 선택기의 기본 테두리가 흰 배경과 1.25:1로 측정됐다. 텍스트는 읽혔지만 입력 경계의 3:1 기준을 충족하지 않아, 언어 선택기도 검색 입력과 같은 `--muted-foreground` 경계를 사용하도록 수정했다.

`node scripts/audit-contrast.cjs`를 밝은 테마·어두운 테마와 꾸미기·장비 패널에서 다시 실행해 텍스트 대비 4.61:1 이상, 입력 경계 3:1 이상, 실패 0건을 확인했다. 640px·320px 재배치와 스위치 키보드 조작도 함께 통과했다.

## 26차 검토: 모바일 라인업 정보 밀도

3–5인 카드의 장비 정보는 캐릭터 수가 늘수록 열 너비가 줄어들어, 320px에서 한국어 이름·보조 언어명이 같은 줄에 함께 표시될 때 작은 글자가 겹쳐 보일 수 있었다.

- 카드 컨테이너 폭이 540px 이하이면 주 아이템명은 최소 8px로 유지하고 보조 언어명은 숨긴다. 보조 언어명은 인스펙터에서 계속 확인할 수 있어 카드의 시각적 계층을 방해하지 않는다.
- `multi-info-column`의 접근 가능한 이름에는 해당 캐릭터의 전체 장비명을 포함해 시각적으로 줄인 정보가 스크린리더에서 사라지지 않게 했다.
- `node scripts/check-card-readability.cjs`가 기존 32개 배경·인원수 조합에 더해 320px 5인 카드의 최소 글자 크기, 보조 줄 숨김, 가로 넘침을 확인한다.

## 27차 검토: 제목 맞춤과 문구 편집 맥락

긴 제목이나 폭이 넓은 선택 서체를 적용하면 카드 제목이 고정 한 줄 슬롯에서 오른쪽으로 잘려 보일 수 있었다. 제목 서체 선택도 카드 배경 설정 하단에 떨어져 있어 문구를 쓰는 흐름이 끊겼다.

- 카드 제목의 실제 글리프 폭을 제목 영역의 반응형 너비와 비교해 필요한 경우에만 최소 12px까지 자동 축소한다. 그래도 한 줄에 들어가지 않는 좁은 카드에서는 제목을 자연스럽게 감싼다. `ResizeObserver`와 폰트 로드 완료 시점을 함께 사용해 창 크기와 서체 변경에도 다시 맞춘다.
- 제목 서체·굵기 컨트롤을 `카드 문구` 섹션 바로 아래로 이동하고 `제목에만 적용` 범위를 표시했다. 카드 설정은 비율·배경 작업에 집중한다.
- 인스펙터 헤더에 반응형 하단 여백을 추가해 `상세 편집`·현재 패널명이 경계선에 닿지 않게 했다. `초기화`는 테두리·hover·focus 피드백을 가진 실행 버튼으로 정리했다.

`node scripts/check-editor-layout.cjs`가 긴 제목의 실제 `scrollWidth`, 12px 글자 크기 하한과 필요한 줄바꿈, 447/390/320px 인스펙터 하단 여백·가로 넘침을 확인한다. `node scripts/check-typography-ui.cjs`는 제목 서체 컨트롤이 카드 문구 섹션 안에 있는지 함께 검증한다.

## 28차 검토: 키보드 탐색 경로

데스크톱과 320px 화면에서 Tab 키를 연속으로 이동해도 포커스가 이름 없는 컨트롤이나 숨겨진 패널에 걸리지 않아야 한다. `<label>`로 연결된 입력과 `aria-labelledby` 그룹은 실제 접근 가능한 이름으로 계산해야 하며, 모든 주요 편집 동작은 같은 경로에서 도달할 수 있어야 한다.

- 포커스 가능한 요소가 가시 영역 밖으로 밀려나거나 보이지 않는 상태로 남는지 검사한다. 각 컨트롤은 ARIA 이름, 연결된 label, title, 텍스트 순서로 이름을 확인하고 `focus-visible` 시각 피드백을 유지한다.
- 내보내기, 작업 모드, 룩 목록 접기, 문구 입력, 제목 서체, 초기화까지 핵심 편집 경로를 필수 대상으로 고정한다. 모바일에서도 같은 핵심 동작이 Tab 순서에서 빠지지 않는다.
- 스킵 링크와 마지막 컨트롤 뒤의 순환을 포함해 한 번의 포커스 사이클을 확인하고, 중복 이동으로 테스트가 무한히 늘어나지 않도록 사이클 감지를 둔다.

`node scripts/check-keyboard-route.cjs`가 실제 Edge에서 1280px·320px의 Tab 경로를 실행해 이름 없는 포커스, 숨은 포커스, 뷰포트 이탈, 핵심 컨트롤 누락을 검출한다. 현재 결과는 데스크톱 34개·모바일 33개 이름 있는 컨트롤이며 두 경로 모두 통과했다. 브라우저 내장 접근성 트리와 함께 실제 VoiceOver/NVDA 발화는 수동 확인이 남아 있다.

## 29차 검토: 라인업 표현과 초기화 범위

`흐림`·`실루엣` 선택은 구현돼 있었지만 카드 문구와 배경 설정 뒤에 묻혀 3~5인 편집에서 찾기 어려웠다. 실루엣은 모든 활성 캐릭터의 배경 제거가 완료돼야 하므로, 조건을 충족하지 않으면 버튼이 비활성화되고 이유를 같은 그룹의 안내 문구로 설명해야 한다.

- `3~5인 정보`를 캐릭터 구성 바로 아래로 이동해 인원수 선택과 표현 선택을 한 작업 맥락에 묶었다. `실루엣` 버튼은 준비 전에는 비활성화하고, 모든 캐릭터가 준비되면 안내 문구와 카드 렌더링 상태를 함께 갱신한다.
- 헤더의 모호한 `초기화`를 범위 선택 메뉴로 바꿨다. `스타일만 초기화`는 배경·표현·정보량·서체·현재 이미지 배치만 되돌리고 제목·설명·장비는 보존한다. `현재 카드 비우기`는 해당 룩의 문구·장비·인원수·이미지 상태와 스타일을 빈 카드 기준으로 되돌린다.
- `모든 로컬 데이터 삭제`는 이 브라우저의 LOOK BOOK 목록, 이미지 IndexedDB 보관함, 장비 캐시와 폐기된 배경 저장 키를 함께 비운다. 새로고침 후에도 이전 v1/v2 저장 키를 다시 읽지 않으며, 실행 직후 빈 초안 저장을 만들지 않는다.
- 스타일·카드 초기화는 실행 전에 하나의 history snapshot을 남겨 `되돌리기`로 복원할 수 있다. 전체 삭제는 의도적인 폐기 동작이므로 로컬 작업공간을 새 빈 카드로 교체한다. 메뉴는 바깥 클릭·Escape로 닫히고 모바일 뷰포트 밖으로 나가지 않으며, 실행 후 초기화 트리거로 포커스를 돌려 숨겨진 메뉴 항목에 포커스가 남지 않는다.

`node scripts/check-info-reset.cjs`가 3~5인 섹션의 위치와 두 표현 컨트롤, 실루엣 준비 전·후 상태, 스타일 전용 초기화의 데이터 보존, 카드 데이터 초기화·undo, 320px 메뉴 경계를 실제 Edge에서 확인한다.

## 30차 검토: 모바일 룩 검색과 작업 모드 전환

320px에서 룩 검색 입력을 숨긴 채 데스크톱 단축키 `Ctrl/⌘ K`가 같은 요소에 포커스를 보내고 있어, 포커스가 보이지 않는 상태로 남는 흐름을 재현했다. 모바일 화면에서도 목록을 찾고 편집 패널을 오갈 수 있어야 하므로 검색을 별도 토글로 열도록 정리했다.

- 모바일 룩 리본에는 `검색` 버튼을 추가하고, 검색 필드는 리본 아래의 제한된 팝오버로 연다. 열 때 입력창으로 포커스를 보내고 `Escape`·바깥 누르기로 닫은 뒤 트리거로 포커스를 되돌린다.
- `Ctrl/⌘ K`는 데스크톱에서는 기존 입력창을, 920px 이하에서는 모바일 검색 팝오버를 연다. 검색 결과는 기존 목록 필터와 같은 데이터 경로를 사용해 중복 상태를 만들지 않는다.
- 장비 패널로 이동하면 아이템 검색창이 하단 고정 작업 모드 위에 오도록 자동 스크롤하고, 3~5인 정보·실루엣 안내·초기화 메뉴도 같은 320px 흐름에서 도달할 수 있게 유지했다.

`node scripts/check-mobile-a11y-flow.cjs`가 320px Edge에서 모바일 검색 열기·필터·Escape·Ctrl/⌘ K·바깥 누르기, 작업 모드 전환, 하단 레일 가림 여부, 실루엣 비활성 안내, 초기화 메뉴 포커스를 한 흐름으로 확인한다. `prefers-reduced-motion: reduce` 환경으로 실행하며 결과 캡처는 [모바일 접근성 흐름 캡처](../artifacts/ui-mobile-a11y-flow-after.png)다. 실제 iOS Safari 터치 제스처와 VoiceOver/NVDA 발화는 여전히 수동 확인 대상이다.

## 31차 검토: 제목 외곽선과 카드 대비

제목 뒤에 전체 헤더 폭으로 깔리던 흰색 그라데이션은 사진을 잘라 보이게 하고, 배경마다 같은 흰 면을 강제로 만들어 카드의 시각적 위계를 흐렸다.

- 헤더·제목 블록의 불투명 배경과 전체 폭 halo를 제거하고, 제목 글리프 자체에만 선택형 외곽선을 적용했다. 외곽선 색상과 0–6px 두께는 `카드 문구` 섹션에서 함께 조절한다.
- 미리보기는 `-webkit-text-stroke`와 `paint-order`를 사용하고, PNG 내보내기는 같은 색상·두께를 Canvas stroke로 먼저 그려 두 레이어가 어긋나지 않게 했다. 기본값은 `없음`이며 배경을 가리지 않는다.
- 제목 컨트롤은 28px 색상 버튼, 키보드 라디오 이동, live 두께 값으로 구성해 작은 원형 버튼 때문에 생기는 접근성 누락을 없앴다.

`node scripts/check-title-outline.cjs`가 헤더·제목 블록의 투명 배경, legacy halo 토큰 부재, 기본 외곽선 없음, 색상·두께 미리보기와 v3 저장값을 실제 Edge에서 확인한다.

## 32차 검토: 빈 LOOK BOOK와 운영 데이터 경계

초기 화면에 고정된 캐릭터·아이템·룩 샘플이 남아 있으면 새 사용자가 자신의 작업공간과 예시 콘텐츠를 구분할 수 없고, 초기화 후에도 데모 이미지가 다시 나타난다.

- 앱 시작값을 `새로운 룩` 한 장과 이미지가 없는 1인 슬롯으로 바꿨다. LOOK BOOK는 사용자가 `새 룩`을 추가했을 때만 늘어나며, 장비 검색은 서버가 반환한 실제 결과만 메모리에 등록한다.
- 장비 부위 표시는 추상 기호 대신 `모자`, `티셔츠`, `장갑`, `바지`, `신발`, `무기`를 사용하고, 보조 접근성 이름에는 기존 canonical 슬롯명을 함께 남겼다.
- 공개 번들에서 데모 스크린샷 자산을 제거하고, 배경 제거 벤치마크 도구는 외부 입력 경로를 명시적으로 받도록 바꿨다. 운영 정적 자산에는 사용자의 로컬 이미지나 테스트 캐릭터가 포함되지 않는다.

`node scripts/check-info-reset.cjs`는 빈 초기 상태, 3인 실루엣 준비, 카드 범위 초기화, LOOK BOOK 추가와 전체 로컬 삭제를 한 흐름으로 확인한다. `node scripts/check-equipment-ui.cjs`는 직관적인 부위 라벨과 320px 리플로우를 확인한다.
