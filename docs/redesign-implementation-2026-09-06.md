# 승인안 구현 기록

기준일: 2026-09-06. 전체 검수 제안서에 대한 구현 후 기록이다.

## 반영된 내용

- 카드별 이미지·인원수·배치·비율·표현 상태를 editor 데이터로 분리했다. models/look-editor.js가 초기 상태·정규화·스냅샷을 담당한다. 기존 v3 공용 이미지는 선택된 카드에 보존한다.
- 카드 전환 시 각 카드의 실행 취소 이력을 유지한다. 원본 교체는 새 assetKey를 사용하고, 카드 비우기는 실행 취소가 참조하는 이미지를 보존한다. 카드와 이력에서 참조되지 않는 자산은 정리한다.
- 저장 성공/실패 상태를 표시한다. 전체 삭제 실패는 성공으로 숨기지 않는다. 전체 삭제에는 범위를 설명하는 확인 창과 취소 동작을 추가했다.
- 꾸미기에 이미지·문구·배경 바로 이동을 추가했다. 충분한 높이의 모바일에서는 축소 미리보기와 편집 항목 내비게이션을 스크롤 중에도 유지한다. 화면이 낮을 때는 자연스러운 문서 흐름을 사용한다.
- 속성 패널의 주요 글자 크기를 12–16px로 정리했다. 슬라이더는 얇은 트랙과 원형 손잡이를 사용하며 제목 외곽선의 조작 영역은 40px다.
- 장비에 동일한 선 굵기의 모자·상의·장갑·바지·신발 SVG와 텍스트를 함께 표시한다. UI 및 신규 제목 기본값은 Pretendard다.
- PNG의 제목·설명은 미리보기 텍스트의 줄 위치를 캡처해 그린다. 별도의 고정 제목 위치와 말줄임 레시피를 제거했다. 폰트 준비에 제한 시간을 두고 출력 중 상태를 표시한다.
- Node 서버에 공개 파일 허용 목록과 기본 loopback 바인딩, 잘못된 URL 처리 오류 응답을 추가했다. 공개 파일만 복사하는 빌드 도구와 npm 잠금 파일, 공통 검사 실행기를 추가했다.

## 실제 검증

- 기존 항목 및 신규 카드/출력 검사를 포함한 회귀 30개 통과. 제목 후광 검사의 별칭은 중복 집계에서 제외했다.
- 추가 서버 검사는 별도 로컬 프로세스에서 필수 파일 제공, 소스·설정 차단, 잘못된 인코딩 요청 이후 서버 정상 응답을 확인했다.
- A/B 서로 다른 사진 → 카드 전환 → 카드 비우기/교체 → 실제 이미지 복구 → 새로고침을 확인했다.
- PNG 파일을 실제로 내려받았으며 긴 제목 전체가 텍스트 그리기에 포함되는지 확인하고 결과 이미지를 열어 검수했다.
- 390px 미리보기 유지와 속성 입력 화면을 확인했다. 대비 검사, 키보드 경로, Pretendard, 장비 선택, 이미지 직접 배치, 전체 삭제 취소/확정 검사 통과.

## 완료로 간주하지 않은 범위

- app.js 전체 기능 모듈 분해와 기존 CSS의 전면 정리는 끝나지 않았다. 카드 상태 모듈과 오류가 있던 핵심 경로부터 분리·수정했다.
- 모든 원본 이미지/선택 서체/인원수 조합의 미리보기와 PNG 픽셀 동일성은 보증하지 않는다. 출력 검증은 긴 문구·줄바꿈·외곽선, 서체 준비 순서와 실제 PNG 생성 경로다. 다른 이미지·장비 레이어는 후속 검수 대상이다.
- 모바일 소프트 키보드, 실제 iOS Safari/VoiceOver/NVDA, 운영 GPU·공개 배포 검수는 남아 있다.
- LOOK BOOK의 복제·이름 변경·개별 삭제·삭제 취소는 후속 단계에서 구현했다. 썸네일 중심 목록은 적용하지 않았으며 현재 DESIGN.md의 번호 기반 탐색 규칙을 유지한다.
- 일부 레거시 UI 보조 글자 및 컨트롤은 추가 통합 대상이다. 전체 리디자인 완료나 배포 승인으로 보고하지 않는다.

검수 캡처: [모바일](../artifacts/redesign-mobile.png), [PNG 출력](../artifacts/redesign-export.png). 자동 검사 집계는 artifacts/check-results.json에 남긴다.

## 중단 지점 재검수 및 후속 수정

- 여러 이미지 가져오기의 각 저장 사이에 카드 전환이 가능해 나머지 사진이 다른 카드로 들어가는 경로를 수정했다. 한 번의 가져오기는 최초 카드에 동기적으로 연결하고, 저장 완료 후 다른 카드의 선택 상태를 덮어쓰지 않는다.
- 전체 삭제는 진행 중인 원본·배경제거 결과 저장을 기다린 뒤 IndexedDB를 비운다. 이전 가져오기가 삭제 후 초안을 다시 저장하지 않는다. 저장 지연을 주입한 check-import-races.cjs에서 카드 소유권 및 삭제 후 전체 DB 레코드 0건, 초안 없음까지 확인했다. 배경제거는 기존 비동기 대상 격리 검사도 재실행했다.
- PNG는 선택한 서체 로드 후 제목 맞춤 및 줄 위치 측정을 수행한다. 준비 중 카드 내용·언어·선택 카드·작업공간이 바뀌면 출력을 중단하고 재시도를 안내한다. 지연 서체 및 편집 변경 검사를 check-export-copy.cjs에 추가했다.
- 이미지 전용 슬라이더의 중복 트랙·손잡이·높이 덮어쓰기를 제거했다. 공통 40px 조작 영역, 20px 원형 손잡이, 4px 트랙을 사용한다. 확장 도크는 여백을 조정해 기존 최대 220px 검사도 유지했다.
- 320px 모바일 캡처에서 저장 문구가 잘게 줄바꿈되는 현상을 확인해 헤더의 마지막 nowrap 덮어쓰기를 수정했다. 이미지 편집 모드의 고정 헤더 행 높이도 콘텐츠 기준으로 바꿔 캔버스 도구와 겹치지 않게 했다. 도크 검사에 실제 헤더/도구 좌표 비교를 추가했다.
- 빌드의 HTML 자산 참조 검사에 models 경로를 포함했다. 기존 최초 검수 결과 파일이 후속 실행으로 덮어써진 사실도 제안서에 명시했다.

데이터·출력 수정 후 전체 회귀 32/32 통과. 이후 슬라이더/헤더 CSS 수정은 도크·이미지 배치·헤더와 스타일 경계 검사로 검증하고 전체 회귀도 재실행했다. 자산 저장 공통 처리의 마지막 변경은 가져오기 경쟁 상태·비동기 대상 격리·구문 검사 및 빌드로 별도 확인했다. 전체 모듈 분해, CSS 전면 통합, LOOK BOOK 관리 기능, 실제 기기 검수는 계속 미완료이며 이번 수정으로 완료 처리하지 않는다.

## LOOK BOOK 관리 후속 단계

- LOOK BOOK의 `관리` 버튼에서 이름 변경·복제·개별 삭제·삭제 취소를 제공한다. 이름 변경은 카드 제목과 동일한 값을 사용하고 기존 카드 실행 취소에 포함한다. 입력을 취소하면 제목을 변경하지 않는다.
- models/look-book.js가 사진 원본·배경 제거 결과를 새 자산 키로 복사한다. 사진 저장 실패/누락 시 일부만 복제된 룩을 목록에 추가하지 않는다. 복제본은 원본의 실행 취소 이력을 상속하지 않는다.
- 삭제한 룩과 카드 실행 취소 이력을 세션 동안 유지하고, 자산 정리 대상에서 제외한다. 삭제 취소는 원래 순서에 복원한다. 마지막 룩 삭제 시에는 빈 룩 하나를 만든다. 새로고침 후에는 삭제 취소가 불가능하며, 전체 작업공간 삭제는 복원 목록까지 비운다.
- 복제 중 전체 삭제 또는 원본 룩 삭제가 발생하면 뒤늦은 복제 결과를 추가하지 않는다. 완료 전 부분적으로 기록한 자산은 참조 정리로 회수한다.
- 대화상자의 이름 입력·닫기·키보드 포커스 복귀를 검수했다. 320px에서 초기화 메뉴가 편집 섹션에 가려지는 결함을 실제 클릭 테스트로 발견해, 모바일 인스펙터 헤더의 위치 지정 및 레이어 순서를 수정했다.
- 신규 검사는 실제 사진 업로드, 이름 변경 undo/redo, 서로 다른 복제본 자산 키, 복제본 교체 후 원본 보존, 정리 타이머 이후 삭제 취소, 새로고침 복원, 복제 실패, 지연 복제 중 전체 삭제를 다룬다. 모바일 캡처: [관리 창](../artifacts/look-management-mobile.png), [목록](../artifacts/look-library-mobile.png).

이 단계는 LOOK BOOK 관리 기능 구현이며, 전체 CSS 통합과 app.js의 추가 모듈 분리는 남아 있다. 실제 iOS/스크린리더 및 공개 배포 검수 완료로 확대 해석하지 않는다.

최종 로컬 검증: 전체 회귀 33/33 통과, 앱/두 모델/서버 구문 검사 통과, 스타일 경계 검사 통과, 공개 빌드 생성 및 필수 자산 확인 통과. 새 모델의 로컬 서버 HTTP 제공도 서버 허용 목록 검사에 포함했다.

## 이미지 저장 모듈과 CSS 정리

- app.js 안의 IndexedDB 연결/조회/저장/전체 삭제/참조 정리 구현을 models/image-assets.js로 분리했다. 저장은 트랜잭션 완료 후 성공을 반환한다. 연결 실패 시 다음 호출에서 재연결하며, 복제 불가능한 데이터를 쓰는 오류도 트랜잭션 취소로 처리해 기존 레코드를 보존한다. 호출되지 않는 removeMany는 제거했다.
- 현재 DOM에 없는 image-editor-stage 계열의 격자·십자선·드래그 미리보기 및 반응형 규칙을 제거했다. 완전히 동일한 반복 도크 규칙도 제거했다. editor-controls.css에서 2,531자를 줄였으며 기존 DESIGN.md는 변경하지 않았다.
- 신규 check-image-asset-store.cjs는 실제 브라우저 IndexedDB에서 초기 연결 실패 후 재시도, 원본과 배경 제거 결과 병합, 자산 키 보존, 실패한 쓰기의 롤백, 참조 자산 유지, 전체 삭제를 검사한다.
- 공개 파일 허용 목록, 스크립트 로딩, 구문 검사에 새 저장 모듈을 포함했다. 저장 스키마와 DB 이름은 유지해 기존 작업을 이전 없이 읽는다.

이 단계에서도 전체 리팩터링 완료를 선언하지 않는다. 추가 CSS 통합, 내보내기·검색·UI 제어의 모듈 분리와 실제 기기 검수는 남아 있다.

이미지 저장/CSS 단계 검증: 회귀 34/34 통과. 정리 전 CSS와 비교해 1440/875/320px의 밝은/어두운 테마 6개 조건에서 실제 도크 DOM의 계산된 크기·배치·타이포그래피·색상·테두리가 일치했다. 픽셀 스크린샷 전체 동일성 검사로 확대하지 않는다. 구문·스타일 경계·빌드 검사 통과.

## 검색 요청 모듈 후속 분리

- models/item-search.js가 요청 취소, 늦은 응답 무시, 검색어 정규화, 언어/부위별 캐시, 만료 및 최대 100개 캐시 항목 관리를 담당한다. app.js는 입력 지연과 검색 상태의 화면 표현을 담당한다.
- 전체 작업공간 삭제 시 요청 및 캐시뿐 아니라 장비 검색과 LOOK BOOK 검색 입력도 비운다. 삭제 직후 이전 검색어로 결과를 다시 불러오는 경로를 제거했다.
- check-item-search-model.cjs에서 취소를 무시하고 늦게 도착한 응답, 캐시 언어/부위 격리, 정규화, 만료, 용량 제한, 서버의 오래된 결과 표시, 잘못된 응답을 검사했다. 기존 전체 삭제 검사에는 검색 입력 초기화 확인을 추가했다.
- 공개 서버 허용 목록과 빌드/구문 검사에 검색 모듈을 포함했다. 추가 CSS 통합, 내보내기·UI 제어 모듈 분리, 실제 기기 검수는 여전히 남아 있다.

검색 분리 후 최종 검증: 전체 회귀 35/35 통과. 구문 검사, 공개 빌드, 스타일 경계 검사 통과. localhost:4173에서 새 검색 모듈 제공을 확인했다.

## PNG 그리기 모듈 분리

- models/card-png.js로 배경·패턴·사진 배치·그림자/외곽선·제목·장비 정보·PNG 변환을 분리했다. 그리는 동안 편집 DOM이나 전역 아이템 저장소를 읽지 않는다.
- app.js에서 시작 시점의 장비 이름·보조 이름·부위 이름을 확정해 전달한다. 서체 준비, 미리보기 제목 줄 측정, 편집 상태 변경 감지와 다운로드 버튼 피드백은 UI 쪽에 유지했다.
- 실제 PNG를 디코딩한 RGBA 픽셀의 SHA-256을 변경 전 구현과 비교했다. 1인 세로, 1인 가로, 2인, 3인, 5인 구성에 dots/stars/halftone/bitmap, grain, 원본/배경 제거를 조합한 5건 모두 일치했다. 결과는 artifacts/png-refactor-comparison.json이다. 이는 리팩터링 전후 출력 보존 검증이며 미리보기와 PNG의 모든 조합이 동일하다는 뜻은 아니다.
- 기존 긴 제목 전체 보존, 서체 로드 대기, 준비 중 편집 변경 시 출력 중단 검사도 통과했다. 공개 서버 및 빌드 검사에 새 모듈을 포함했다.

추가 UI 제어 모듈 분리, CSS 전면 통합, 모든 실기기 검수는 아직 미완료다.

PNG 분리 최종 검증: 전체 회귀 35/35 통과, 구문 검사 및 공개 빌드 통과. 실제 출력 파일도 열어 제목 줄바꿈과 외곽선을 확인했다.

## UI 제어 내비게이션 모듈 분리

- models/editor-navigation.js가 패널 ID 정규화, 탭·라디오 그룹의 roving focus 계산, Home·End 및 방향키 이동, Escape 처리 우선순위를 담당한다. DOM 조작과 포커스 이동은 app.js 어댑터에 남겨 모듈의 인터페이스를 작게 유지했다.
- 앱의 작업 모드 탭과 인원 선택 그룹이 같은 이동 규칙을 사용한다. 유효하지 않은 패널, 비정상적인 현재 인덱스, 빈 그룹을 안전하게 처리한다.
- Escape는 열린 네이티브 대화상자를 건드리지 않고, 초기화 메뉴와 모바일 LOOK BOOK 검색을 순서대로 닫는다. 이미지 배치 모드 단축키와 충돌하지 않는다.
- check-editor-navigation-model.cjs가 패널 fallback, 방향키 순환, Home·End, 경계값, 잘못된 키, Escape 우선순위를 검사한다. 기존 데스크톱·모바일 키보드 경로도 다시 실행했다.
- 새 모델을 공개 서버 허용 목록·HTML 로딩·구문 검사에 포함하고 localhost:4173에서 HTTP 200을 확인했다.

내비게이션 분리 후 최종 검증: 전체 회귀 36/36 통과, 구문 검사, 스타일 경계 검사, 공개 빌드 통과. CSS 전면 통합과 실제 iOS/스크린리더 검수는 여전히 남아 있다.

## 배경 프리셋 데이터 모듈 분리

- models/background-presets.js가 단색·패턴·질감의 허용값, 세 축 시그니처, 표시 이름, 잘못된 저장값 정리, 중복 제거, 최대 18개 제한, 추가·조회·삭제 규칙을 담당한다. localStorage와 DOM은 app.js에 남겨 저장 실패가 화면을 막지 않도록 했다.
- 새 프리셋은 이름을 28자로 정리하고 빈 이름이면 현재 배경 조합을 사용한다. 동일한 세 축 조합은 두 번 저장할 수 없으며, 로드 시에도 먼저 저장된 조합을 보존한다.
- check-background-presets-model.cjs가 기본값·긴 이름·누락 ID·중복 로드·용량 제한·중복 저장·조회·삭제를 검사한다. 공개 서버 allowlist와 HTML 로딩 순서에도 새 모델을 포함했다.

배경 프리셋 분리 후 최종 검증: 전체 회귀 37/37 통과, 구문 검사, 스타일 경계 검사, 공개 빌드 통과. 실제 iOS/스크린리더 수동 검수와 전체 CSS 통합은 여전히 남아 있다.

## 제목 서체 규칙 모듈 분리

- models/title-typography.js가 제목 서체 레지스트리, Pretendard 기본값, 지원 굵기 정규화, 굵기 선택지 생성과 단일 굵기 서체의 숨김 규칙을 담당한다. app.js는 select와 radio UI를 렌더링하고 현재 편집 상태를 저장한다.
- 서체별 지원 굵기는 한 곳에서 정렬·중복 제거한다. 저장 데이터에 알 수 없는 서체가 들어오면 기본 서체로, 지원하지 않는 굵기가 들어오면 가장 가까운 지원 굵기로 복원한다.
- check-title-typography-model.cjs가 fallback, 가장 가까운 굵기, 단일 굵기 숨김, 긴 굵기 목록의 선택지, Pretendard 기본값을 검사한다. 서버 allowlist·HTML 로딩·구문 검사에도 새 모델을 포함했다.

서체 규칙 분리 후 최종 검증: 전체 회귀 38/38 통과, 구문 검사, 스타일 경계 검사, 공개 빌드 통과. 실제 iOS/스크린리더 수동 검수와 전체 CSS 통합은 여전히 남아 있다.

## 재개 후 P0 상태·제목 레이아웃 보강

- 전체 로컬 데이터 삭제와 동시에 진행 중이던 아이템 영문명 요청이 완료되면 `saveState()`를 호출하던 경합을 수정했다. 요청 시작 시점의 작업공간 세대와 룩 ID를 저장하고, 삭제·룩 전환 뒤에는 화면 갱신과 저장을 건너뛴다. 삭제 시 남아 있는 언어 요청도 새 작업공간과 분리한다.
- 이미지 보관함 삭제나 브라우저 저장소 삭제가 실패하면 확인 대화상자를 성공으로 닫지 않는다. 사용자는 실패 상태를 확인하고 다시 시도할 수 있다.
- 모바일 뷰포트 변경 시 `ResizeObserver` 전달을 기다리지 않고 제목 맞춤을 한 번 즉시 실행한다. 447·390·320px에서 긴 제목의 콘텐츠가 고정 데스크톱 스타일로 잘리는 회귀를 `check-editor-layout.cjs`로 확인했다.
- 세부 스타일 토글의 `aria-controls`가 실제 테두리·그림자 섹션 ID를 가리키도록 수정하고 스크린리더 의미 검사를 추가했다.

이 보강 단계의 회귀 검사에는 지연 아이템 요청 삭제 경합을 포함한다. 전체 회귀 39/39, 구문 검사, 공개 빌드, 스타일 경계 검사를 통과했다. 전체 CSS 전면 통합과 실제 기기 검수는 여전히 후속 범위다.
